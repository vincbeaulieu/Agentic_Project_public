# 04_rules_and_code_of_practice — index

This folder holds the human-authored rules that govern the organization's agents: their code of practice and the standards their outputs must meet. They are the normative source for the corresponding sections of the development plan (D3) and for the machine-enforced controls in the kernel (D5). The rule texts are stored verbatim as issued by the project owner; each file adds only a header (status, scope, enforcement, amendment procedure) and, where the owner issued clarifications, an amendments section quoting them verbatim.

## Relation to other governance artifacts

The constitution (`prototype/seed_kernel_v*/constitution.toml`) is the machine-enforced subset of these rules plus the project-specific limits (paths, budgets, phrases). Where a rule can be enforced by code, the kernel enforces it and the rule text is informational for the agent; where it cannot, the rule is stated in the agent's instructions and enforced at review. The principle-to-enforcement maps in `03_audits_and_reviews/` record which is which for each provision.

Precedence when texts differ: the constitution (machine-enforced) > these rules > D3 > D4 > agent-specific instructions. A conflict between a rule and the constitution is an escalation condition and is resolved by the human.

## Amendment procedure

A rule is amended by adding a new version file (`R0n_..._v2.md`) and a line in the workspace `CHANGELOG.md`; earlier versions remain. A clarification issued by the owner is recorded verbatim in an amendments section of the next version (or, as in R02 v1, in the same version when the clarification was issued before the file was first written). The corresponding D3 section, kernel prompt text and tests are updated in the same change, and the kernel's constitution hash change is recorded in the audit log at the next start.
