# Method workspace — public edition (v1.0.0, 19 October 2026)

This folder is the public edition of the workspace in which an AI assistant (Claude) and I built, tested and enforced a working
method for AI-assisted technical work in a regulated setting. It is the practice that comes before the governance kernel in
`02_prototype/`: here the controls are applied to real work by an assistant under rules I set; the kernel turns the same principles
into a default-deny platform that the agent cannot bypass.

The workspace grew out of one task: revising a long technical report with AI help, where every change had to be traceable,
justified and reversible, as design control requires in regulated engineering work. Each time the model failed, the
failure was turned into a deterministic tool that the model must use and into a written lesson tied to an automatic check. The
model never approves its own work: methods, lessons and skills it proposes stay proposals until I accept them.

## Principles

- **Deterministic evaluation over model judgment.** Written rules are checked by versioned scripts with hard rules, not by a
  language model. A deliverable is handed over only after the evaluator returns *compliant*.
- **Never overwrite.** Every change produces a new version of the file; successive checksum manifests prove it.
- **Every tool is versioned and tested.** A new version is adopted only if its tests pass, including a negative test that first
  proves the defect exists on the previous version (lesson LC-032).
- **Every failure becomes a control.** A lesson is a JSON record with its rule, its evidence and the check that enforces it;
  recurrences are tracked.
- **Delegation is evaluated.** Work given to other agents has a typed output and a deterministic evaluator, which the lead agent
  re-runs itself; weaker and stronger agents check each other's work, and the lead solves the task alone as a reference.
- **Reuse before writing.** The tool catalogue is searched before any new script is written.
- **A diagnosis is a hypothesis until the source confirms it** (lesson LC-036).
- **No personal names** in the workspace's own documents: "the user", "Colleague A".

## Running it

Python 3.10 or later; LibreOffice and poppler for the Word tools; PowerShell (`pwsh`) for the Windows-side scripts.

```
python3 outils/tester_outils.py          # all tests and smoke tests
python3 outils/catalogue.py              # regenerate the catalogue from the tool headers
python3 outils/chercher_outil.py <words> # search the catalogue before writing anything
python3 outils/evaluer_travail.py <work folder>
python3 outils/balayer_termes.py regles_travail/lexique_exemple_v1.json <folder> [--md report.md]   # confidential-term scan
```

Tools are always called through their shortcut (`outils/<tool>.py`), never as `<tool>_vN.py`.

## What this edition leaves out, and why

- Personal and project data: people, organisations and partners, and the subject matter of the report the method was built on,
  are replaced by neutral, invented content; paths to my computer are removed. Test fixtures that came from the real report use
  invented sentences and labels. Before publication, every file was scanned with `outils/balayer_termes.py` against a private
  lexicon of confidential terms and read by an independent reviewer agent. Each residue the reviewer found was replaced at its
  source, added to the lexicon as a recall case, and the scan run again in strict mode until no finding was left unreviewed.
- Records of the work itself: tool event journals, delegation records, dashboard data, daily reviews, classifier training data,
  test-run archives and backup copies.
- The encrypted GitHub backup relay (a candidate tool tied to my private storage) and its tests.
- The role and protected-name lists are empty: in a private workspace they hold truncated SHA-256 fingerprints, never names.

## Language

The documents (rules, lessons, catalogue, memo, guide, procedure, skills) are translated into English. The code is not: identifiers,
comments and messages stay in French, because the tools match French strings (comment prefixes such as `Fait :` "Done:", status
labels, folder names). The translations keep these strings verbatim and give their meaning on first use.

## Test status of this edition

Run on 19 October 2026 on a copy of this folder (Linux, Python 3.13): `python3 outils/tester_outils.py`

- smoke tests: 43 tools, 0 failures;
- unit tests: 1,210 tests, 0 failures, 7 skipped (5 compare with an older catalogue version that does not know the regenerated
  registry; 2 need real deliverables that are not published);
- integration benches are not run by default (`python3 outils/tester_outils.py --complet`).

Known limitation: one negative-control test of `livrer` (`FicheTravail.test_defaut_present_avec_la_cle_v4`, run by the v5 to v8
suites) reads a version number from the full path of its temporary folder. If the folder that holds the workspace has a
`_v<digits>` segment in its name (for example `project_v2/`), that test fails six times; the tool is not affected. Place the
workspace under a path without such a segment.
