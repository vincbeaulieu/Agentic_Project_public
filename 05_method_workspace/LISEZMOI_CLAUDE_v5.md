# Claude's competence workspace — entry point (v5, 16 Oct. 2026)

This folder is the workspace where I automate my competences. It is located in `/home/claude/00_competences_claude/` and, on the PC, in `Revision\00_competences_claude\`. No person's name appears in it: we write "the user", "the colleagues".

**v4: descriptive folder names and a central path register.** Each tool designates a folder by its logical key, for example `chemin('lecons')` (`cc_lib_v4`). The real name is read from `outils/_gestion/chemins_vN.json`. Renaming a folder therefore amounts to updating this register, recording the move and replaying it on the PC, without a new version of the tools.

In tool headers (`BANC: tests/…` ("TEST BENCH"), `ENTREES: lecons/…` ("INPUTS")), paths are **logical**: the first segment is the key, not necessarily the real name.

**v5: reuse first, call through the shortcut, three tool levels** (skill `cadre-travail-deterministe` v6).
- Before writing a script or a tool, even a project script, search: `python3 outils/chercher_outil.py <mots-clés>`, then in the project scripts and the skills' resources. Every new script carries `CATALOGUE CONSULTÉ : <requête> → <résultat>` ("CATALOGUE CONSULTED: <query> → <result>") at the top.
- A tool is always called through `python3 outils/<outil>.py`. Never a `_vN.py` file, never PYTHONPATH pointing to `outils/`. An import error is information about the call, to be read, never to be worked around.
- Levels:
  - **foundation**: common library (`cc_lib` v5, which fails loudly on a wrong root), shortcuts, test helpers;
  - **base**: one specific problem;
  - **procedures**: they chain base tools through their shortcuts, with no logic of their own (`livrer` v4 and its docx delivery gate).
- A diagnosis remains a hypothesis until the source has confirmed it, and a "0" is checked against an independent count (LC-036).

## Organization

| Folder (logical key) | Role |
|---|---|
| `memoire_methodologique/` (`memoire`) | Versioned methodology memo; only the latest approved version is authoritative (`outils/memoire.py courant`) |
| `guides_methode/` (`guides`) | **Imperative rule**: search for a tool before programming, generalize rather than duplicate, test, adopt (`GUIDE_creation_outils_vN.md`) |
| `procedures_exploitation/` (`procedures`) | Operating procedures, including the LM Studio worker (start, restart, use) |
| `outils/` | One folder per tool: `outils/<outil>/<outil>_vN.*` is the current version, `archive/` holds the previous ones, `candidat/` the draft in progress, never run by the shortcuts. At the root: the shortcuts `outils/<outil>.py`, `_compat/` (old imports), `_gestion/` (tool register, **path register**, change log, plans, recorded moves) and the engine `_raccourci_vN.py` |
| `tests_outils/` (`tests`) | Unit and integration tests (`test_<outil>_vK.py`), replaced suites in `archive/`, reports (`rapports/`), trials (`_test_execution/`) |
| `catalogue_outils/` (`catalogue`) | Tool dictionary, generated by `outils/catalogue.py` |
| `regles_travail/` (`regles`) | Rules verified by `evaluer_travail`, roles, protected names |
| `lecons_apprises/` (`lecons`) | One lesson per immutable JSON file, and its register |
| `taches_types_automatisables/` (`taches`) | Task types and their automatable steps, absence plans and logs |
| `delegations_agents/` (`delegations`) | Delegations to agents: briefs, deterministic evaluators, measured results |
| `bancs_essai_outils/` (`bancs`) | Fixed cases of the test benches and results by version |
| `entrainement_classifieurs/` (`entrainement`) | Training directory for the classifiers I develop: specifications, gold / silver / bronze data, embeddings, models and checkpoints, benches |
| `revues_audits_quotidiens/` (`revues`) | Audits (trees, statuses, reports) and the mentor's daily reviews |
| `skills_atelier_de_propositions/` (`skills_atelier`) | Complete drafts of the skills I write, one version per file |
| `skills_propositions_a_reviser/` (`propositions`) | Everything that awaits the user's decision; index and audit of the proposals (`outils/suivre_propositions.py`) |
| `skills_ressources_par_skill/` (`skills_ressources`) | Skill resources, coming from the `skills` folder at the root of `Revision`: old versions, reference scripts, examples, performance registers |
| `journal_evenements_outils/` (`journal`) | One immutable event per tool run |

## At the start of each session

1. Restore the workspace from the PC if it is missing from the cloud.
2. Read the approved memo: `python3 outils/memoire.py courant`.
3. Read this file, the latest catalogue and the lesson register, without rereading the tools.
4. `python3 outils/organiser_outils.py verifier`, then `python3 outils/tester_outils.py`. Both must be compliant.
5. `python3 outils/lecons.py verifier`, `python3 outils/delegation.py verifier`, `python3 outils/verifier_sauvegarde.py`.
6. State of the LM Studio worker (procedure, § 1); remind the user of pending approvals (`outils/suivre_propositions.py etat`).

## Essential commands (always through the shortcuts)

| Need | Command |
|---|---|
| Find a tool | `python3 outils/chercher_outil.py <mots-clés>` |
| New version of a tool | `outils/organiser_outils.py preparer <outil>` (draft in `candidat/`) → modify → tests → `outils/organiser_outils.py adopter <outil>` |
| Test everything | `python3 outils/tester_outils.py [--complet] [--candidat outil=N]` ; the tests of one tool: `--outil <outil>` ; one suite, one class or one test only: `--test test_<outil>_vK[.Classe[.test]]` (v4: full failure messages, skipped tests counted, smoke test of the candidates) |
| Evaluate a work folder | `python3 outils/evaluer_travail.py <dossier>` |
| Hand over a deliverable | `python3 outils/livrer.py <dossier> <fichier>:<Nom>` ; a docx goes through the gate (v4): `--reference <rapport.docx>` (or `--sans-reference "<motif>"`) ; first `--porte-seule` to render the pages, look at them, then hand over with `--pages-vues 1,3,… [--images-vues N]` |
| Check a docx | `python3 outils/valider_xsd.py <docx> --paquets <dossier>` (absolute XSD) ; `python3 outils/rendre_docx.py <docx> --sortie <dossier neuf>` (real opening, PNG pages, images) ; `python3 outils/controler_mise_en_forme.py reference <rapport.docx> <docx>` (format identical to the report) |
| Test bench | `python3 outils/banc.py <outil> --comparer N M` |
| LM Studio micro-tasks | `outils/microtaches.py` (split, combine, evaluate) ; `outils/file_lmstudio.py` (drop, collect) |
| Classifiers | `outils/donnees_entrainement.py collecter …` ; `outils/entrainer_classifieur.py entrainer …` |
| Workspace audit | `python3 outils/auditer_espace.py [--racine …] [--complet]` |
| Proposals and decisions | `python3 outils/suivre_propositions.py detecter|rapport|etat` |
| Rename a workspace folder | JSON plan via `outils/renommer.py`, new version of `outils/_gestion/chemins_vN.json`, recorded move (`organiser_outils.py consigner`) |
| After a backup to the PC | On the PC: `python3 outils/organiser_outils.py rejouer` (recorded moves), then `verifier` |
